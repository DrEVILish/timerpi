# TimerPi — Bug Log

> Every defect found by the full code review of 2026-10-06 (branch
> `docs/reset-2026-10` at `c8b8936`), one row per issue. This is the
> working list: when you fix one, set its **Status** to `Fixed <date>`
> with the commit, and land a test with it (AGENTS.md). New bugs get the
> next free ID in their severity group. STATUS.md §4.1 points here.

**IDs:** `RC` = Critical, `RW` = Warning, `RS` = Suggestion. They don't
collide with the PRODUCT (E, T, S, A, L, H, M) or STATUS (B, N, C, H) IDs.

**Severity:**
- **Critical:** crashes the box, corrupts a running show, breaks a core feature, or lets an outsider take control.
- **Warning:** wrong behaviour, a real security gap, or a load problem at the 200–1,000-phone target.
- **Suggestion:** hardening, tidy-up or a small edge case.

**Method:** five parallel reviews (access, audience, screens, engine/database, browser/device code). Most findings were confirmed by throwaway tests outside the repo, and RC1–RC4, RC8, RW1, RW5 and RW17 were re-checked by hand. At review time `go vet` and `go test -race ./...` were clean, so none of these show up in the existing tests.

**Suggested order:** RC1–RC8, then the security warnings RW1–RW16, then performance RW53–RW58 before the H5 load test on a Pi.
